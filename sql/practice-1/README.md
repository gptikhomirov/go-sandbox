## Подсказки и теория по задачам

### [01. Активные пользователи](./01-active-users.sql)

**Что нового.** Самая базовая форма `SELECT cols FROM table WHERE cond`. Колонки в `SELECT` перечисляются через запятую, **без** скобок:

```sql
SELECT id, name, age   -- ✓
SELECT (id, name, age) -- ✗
```

### [03. Пользователи не из Москвы](./03-not-from-moscow.sql)

**Что нового.** Оператор неравенства `<>` (в Postgres также работает `!=`, но `<>` — стандарт SQL). Альтернатива: `WHERE NOT city = 'Moscow'`. Попробуй оба варианта и выбери более читаемый.

**Подсказка.** Строковые литералы в Postgres — одинарные кавычки: `'Moscow'`. Двойные кавычки используются для идентификаторов (имён колонок/таблиц).

---

### [04. Пользователи из нескольких городов](./04-moscow-or-berlin.sql)

**Что нового.** Конструкция `IN (..., ...)` — короткая запись для `col = a OR col = b OR ...`:

```sql
WHERE city IN ('Moscow', 'Berlin')
```

Если городов 5+, `IN` сильно читаемее, чем `OR`.

**Что попробовать.** Сначала напиши через `OR`, потом перепиши через `IN` — увидишь разницу в шуме.

### [05. Возрастной диапазон](./05-age-range.sql)

**Что нового.** `BETWEEN a AND b` — короткая запись для `col >= a AND col <= b`. **Границы включительные**.

```sql
WHERE age BETWEEN 20 AND 30
```

**Что попробовать.** Перепиши то же самое через `>=` и `<=` — убедись, что результат тот же.

### [07. Топ-5 самых старших активных](./07-oldest-users.sql)

**Что нового.**
- `ORDER BY col DIRECTION` — сортировка. По умолчанию `ASC` (по возрастанию). Для убывания — `DESC`.
- `LIMIT N` — обрезать вывод до N строк. **Всегда** идёт после `ORDER BY` — иначе попадут случайные строки.

**Правильный порядок секций:**

```sql
SELECT ...
FROM ...
WHERE ...
ORDER BY ...
LIMIT ...
```

### [09. Москвичи или взрослые](./09-moscow-or-old.sql)

**Что нового.** `OR` — логическое ИЛИ между условиями. В отличие от `IN`, которое работает по **одной** колонке, `OR` нужен когда условия — по **разным** колонкам или с разными операторами.

```sql
WHERE city = 'Moscow' OR age > 35
```

**Подсказка про приоритеты.** `AND` имеет приоритет выше, чем `OR`. Когда комбинируешь `AND` и `OR` — ставь скобки явно:

```sql
WHERE is_active
  AND (city = 'Moscow' OR age > 35)
```

Без скобок Postgres прочтёт это как `(is_active AND city = 'Moscow') OR age > 35` — почти всегда не то, что хотели.

**Что попробовать.** Убери скобки — посмотри, как изменится результат и почему.
